# Team formation persistence

The app now keeps the current published SVG path **and** stores the structured formation document beside it.

## Quick path

1. Apply `supabase/migrations/20260619_add_country_formation_json.sql`.
2. Dry-run all canonical formations: `pnpm formation:upload-batch`
3. Real upload of all 48 teams: `pnpm formation:upload-batch -- --write`

## Storage contract

| Location | Contents | Why it exists |
|---|---|---|
| `public.country.formation` | Raw inline SVG generated by `renderFormationSvg()` | Preserves the current published/read path with no UI breakage |
| `public.country.formation_json` | Structured `createFormationDocument()` payload (`schemaVersion`, team metadata, pitch metadata, positioned players, optional source/match metadata) | Keeps future UI rendering data queryable without parsing SVG |

## Why both columns exist

- `country.formation` stays the backward-compatible source for existing SVG-only reads.
- `country.formation_json` adds a stable structured contract for future formation UI work.
- Writing both in the same upload step keeps the two representations in sync.

## Team-page render contract

- `/teams/[slug]` SHOULD re-render the published formation graphic from `country.formation_json` when the structured document is valid.
- The app-side render uses the same resolved team accent token for player markers and keeps player labels on a light capsule with dark text for stable readability.
- `country.formation` remains the fallback path when a legacy team only has stored SVG or the JSON payload is invalid.

## Commands

```bash
# Validate all canonical team formation inputs without writing to Supabase
pnpm formation:upload-batch

# Upload all 48 canonical formations after the migration is applied
pnpm formation:upload-batch -- --write
```

## Text authoring contract

Use the same text contract in both `pnpm formation:preview` and `pnpm formation:upload`.

```text
<country-slug> <formation>
<number> <full name> <role>
<number> | <full name> | <role> | <short label> | <slot>
```

- Legacy rows remain valid: `10 Lionel Messi FW`
- Extended rows support stable short labels and optional explicit slots: `10 | Lionel Messi | FW | Messi | RW`
- `label` defaults to `name` when omitted or left blank
- `slot` is optional, but recommended when you want deterministic placement for repeated edits

## Notes

- Do not remove or repurpose `country.formation`; existing readers still expect SVG there.
- The real upload requires the write-capable Supabase key already used by the local formation uploader.
